Analysis

Objective: Design a competition-ready fully 3D-printed excavation rover for sandy terrain material collection and deposition within a 30×30×30 cm envelope, leading all engineering subteams from concept through competition.

Scope: Directed five concurrent subteams: drivetrain, payload, chassis, electronics, and system integration testing. Full documentation available via the design report.

Validation: Sand-bed testing across multiple configurations; modal analysis on gimbal; FEA across drivetrain and structural components.

50-member team5 subteams led30×30×30 cmSand-validatedCompeting April 2026

Final Design — Anti-Sand Tread: Custom pin-jointed modular track architecture with wide-link geometry and deep sand-displacement grooves. Sprocket-driven with integrated guide features. Individual link replacement without full disassembly.

Prototype — Internal Sprocket: Earlier iteration using an internal sprocket drive, significantly faster but susceptible to sand ingestion. Replaced after sandbox validation.

Sectional Analysis: Cross-section of the final drivetrain reveals sprocket tooth geometry, link-to-sprocket contact interface, track channel walls, and bearing seat load paths — informed wall thickness and print orientation for all load-bearing features.

Validation: Worst-case static load at sprocket contact interfaces; tread link pin connection stress analyzed via FEA.

Structural Section Analysis

Full static FEA performed across the drivetrain assembly. Results informed final wall thickness, pin diameter, and print orientation. Full methodology in the design report.

Gimbal System: Servo-driven two-axis camera gimbal designed to maintain a stable image plane during rover traversal over uneven terrain. TPU/PLA hybrid mount decouples the camera from chassis vibration.

Modal Analysis: Tuned mount natural frequency to servo vibration modes through flexible material and geometry iteration. Image distortion fully eliminated under motor operation.

Design: Entirely 3D-printed — flexible TPU mount interfaces rigid PLA structural arms. The compliant mount acts as a mechanical low-pass filter for high-frequency vibration.

Kresling Origami Mechanism
Active Development

Concept: A spring-activated deployable camera system based on the Kresling origami pattern — a cylindrical structure that simultaneously rotates and collapses along its central axis. When triggered, it snaps from compact stowed state into a fully deployed gimbal platform.

Parametric Design: Fully parametrized in Fusion 360 — panel count, fold angle, cylinder radius, and deployment stroke driven by a single parameter table.

Fabrication: Multi-material FDM, printing flexible and rigid zones in a single pass to eliminate hinges and fasteners.

End Goal: A throwable device that deploys on impact into a stable camera gimbal, surveys for gas leaks or thermal anomalies, and points a laser at detected targets.

Full-Stack IoT · Embedded Systems · Home Network
Autonomous IoT Security System
Multi-Node Embedded System
Overview
Hardware Modules
Software & Control

System overview: A fully self-built home security and automation network integrating over a dozen microcontrollers and sensors. Every module designed, wired, and coded from scratch — no off-the-shelf platforms used.

Modules: Six ESP32-CAM security cameras, a face-tracking pan-tilt system, two laser tripwires, an RFID entry node, a relay array controlling power to multiple zones, and voice activation — all networked through a chain of ESP32 relay nodes.

Why it matters technically: Designing a reliable multi-node embedded network from scratch requires solving real distributed systems problems — signal degradation, message collision, power isolation, and latency. Each solved at hardware and firmware level.

6 ESP32-CAM camerasFace-tracking pan-tilt2 tripwiresRFID nodeRelay arrayVoice activationCloud dashboardESP relay chain

ESP32-CAM cameras (×6): Custom firmware streaming MJPEG over Wi-Fi, triggering motion alerts via GPIO. Mounted in custom 3D-printed housings.

Face-tracking pan-tilt system: Pan-tilt servo platform with centroid-tracking loop detecting face bounding boxes at ~15 fps on-device.

Tripwires (×2): Laser emitter–photodiode pairs firing MQTT messages within ~8 ms on beam break. Operates independently of network state.

RFID node: MFRC522 reader with authenticated UIDs stored in flash. Valid card unlocks relay and logs timestamped entry event.

Relay array: Eight-channel board driven by an ESP32 GPIO expander. Each channel individually addressable from the web interface via MQTT.

Voice activation: Offline keyword detection sending control packets over serial to the nearest relay node.

~15 fps face trackingMFRC522 RFID8-ch relay array~8 ms interrupt latencyOffline keyword detectionMQTT pub/sub

Cloud dashboard (HTML/CSS/JS): Built from scratch without frameworks. Single-page app serving live MJPEG feeds, polling sensor states every 500 ms, rendering relay zone toggles mapped directly to MQTT commands. Loads in <1.5 s on mobile.

Laptop control panel: Python WebSocket server with curses terminal UI. Commands propagate to target nodes in <10 ms local round-trip.

ESP firmware: All node firmware in C++ (Arduino framework). Base class handles Wi-Fi reconnect, MQTT lifecycle, watchdog, and OTA updates. New node type requires ~40 lines of module-specific code.

Relay chain: Each ESP32 operates in dual STA+AP mode. Messages hop as JSON over TCP sockets; 3-hop chain reaches broker in <20 ms. Heartbeat failover with onboard flash logging.
