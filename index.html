Analysis

Objective: Design a competition-ready fully 3D-printed excavation rover for sandy terrain material collection and deposition within a 30×30×30 cm envelope, leading all engineering subteams from concept through competition.

Scope: Directed five concurrent subteams: drivetrain, payload, chassis, electronics, and system integration testing. Full documentation available via the design report.

Validation: Sand-bed testing across multiple configurations; modal analysis on gimbal; FEA across drivetrain and structural components.

50-member team5 subteams led30×30×30 cmSand-validatedCompeting April 2026

Final Design — Anti-Sand Tread: Custom pin-jointed modular track architecture with wide-link geometry and deep sand-displacement grooves. Sprocket-driven with integrated guide features to maintain alignment under abrasive lateral loading. Individual link replacement without full disassembly.

Prototype — Internal Sprocket: Earlier iteration using an internal sprocket drive with a faster, lighter track. Significantly higher top speed but susceptible to sand ingestion between the sprocket and inner track surface, causing derailment under competition conditions. Replaced by the final design after sandbox validation.

Validation: Worst-case static load at sprocket contact interfaces; tread link pin connection stress analyzed via FEA. Sandbox testing across multiple configurations confirmed the anti-sand design’s superiority in loose terrain.

Anti-sand geometryTwo-generation designModular / field-repairablePin FEA validated
Structural Section Analysis

Full static FEA performed across the drivetrain assembly — sprocket bearing loads, link tension at maximum drive torque, and chassis mounting interface stresses. Results informed final wall thickness, pin diameter, and print orientation for all load-bearing components. Full methodology and results in the design report. Analysis images in the Analysis Gallery below.

Gimbal System: Servo-driven two-axis camera gimbal designed to maintain a stable image plane during rover traversal over uneven terrain. Mount geometry and material selected to decouple the camera from structural vibration transmitted through the chassis.

Modal Analysis: Tuned the mount’s natural frequency to servo vibration modes through iterative flexible material selection and geometry changes. Before tuning, servo harmonics induced visible image distortion at operating frequencies. After, distortion was fully eliminated.

Design: Entirely 3D-printed using a flexible TPU mount interfacing rigid PLA structural arms. The compliance in the mount acts as a mechanical low-pass filter for high-frequency vibration, while retaining sufficient stiffness for precise pan/tilt positioning.

In Progress · Deployable Mechanisms
Kresling Origami Mechanism
Active Development

Concept: A spring-activated deployable camera system based on the Kresling origami pattern — a cylindrical structure that simultaneously rotates and collapses along its central axis. When triggered, it snaps from compact stowed state into a fully deployed gimbal platform.

Parametric Design: Fully parametrized in Fusion 360 — panel count, fold angle, cylinder radius, and deployment stroke driven by a single parameter table, enabling rapid iteration without rebuilding geometry.

Fabrication: 3D-printed using multi-material FDM, printing flexible and rigid zones in a single pass to eliminate hinges and fasteners. Fold geometry tuned to minimize supports while maintaining deployment repeatability.

End Goal: A throwable device that deploys on impact into a stable camera gimbal platform, surveys for gas leaks or thermal anomalies, and points a laser at detected targets.

Full-Stack IoT · Embedded Systems · Home Network
Autonomous IoT Security System
Multi-Node Embedded System
Overview
Hardware Modules
Software & Control

System overview: A fully self-built home security and automation network integrating over a dozen microcontrollers and sensors across multiple rooms. Every module was designed, wired, and coded from scratch — no off-the-shelf platforms used. The system runs continuously, reporting live to a custom cloud-hosted dashboard accessible from any phone or laptop.

Modules: Six ESP32-CAM security cameras, a face-tracking pan-tilt system, two laser tripwires, an RFID entry node, a relay array controlling power to multiple zones, and a voice activation module — all networked through a chain of ESP32 relay nodes extending signal range across the building.

Why it’s technically interesting: Designing a reliable multi-node embedded network from scratch requires solving real distributed systems problems — signal degradation, message collision, power isolation between relay stages, and latency between events and dashboard updates. Each was solved at hardware and firmware level.

6 ESP32-CAM camerasFace-tracking pan-tilt system2 tripwiresRFID nodeRelay arrayVoice activationCloud dashboardESP relay chain

ESP32-CAM cameras (×6): Each node runs custom firmware streaming MJPEG over Wi-Fi, triggering motion alerts via GPIO, and reporting health. Mounted in custom 3D-printed housings with adjustable brackets.

Face-tracking pan-tilt system: Pan-tilt servo platform driven by an ESP32 running a centroid-tracking loop — detects face bounding boxes from the onboard stream and continuously adjusts servo positions to keep the target centered at ~15 fps on-device.

Tripwires (×2): Laser emitter–photodiode pairs with dedicated ESP32 nodes. Beam break triggers an interrupt, fires an MQTT message within ~8 ms, and drives a local buzzer independently of network state.

RFID node: MFRC522 reader with authenticated UIDs stored in flash. Valid card unlocks the relay and logs a timestamped entry event; invalid card triggers a network-wide alert.

Relay array: Eight-channel board driven by an ESP32 GPIO expander, controlling power to multiple zones. Each channel individually addressable from the web interface via MQTT.

Voice activation: Offline keyword detection on a dedicated microcontroller. Wakeword triggers command parsing and sends control packets over serial to the nearest relay node, independent of internet connectivity.

~15 fps face trackingMFRC522 RFID8-ch relay array~8 ms interrupt latencyOffline keyword detectionMQTT pub/sub

Cloud dashboard (HTML/CSS/JS): Built from scratch without frameworks. A single-page app serves live camera feeds as MJPEG streams, polls sensor states every 500 ms via REST, and renders zone control toggles that map directly to relay MQTT commands. Loads in under 1.5 s on mobile.

Laptop control panel: A local Python script running a WebSocket server provides lower-latency control when on the home network. A curses terminal UI shows live node status, message rates, and alerts. Commands propagate to target nodes in under 10 ms local round-trip.

ESP firmware: All node firmware in C++ (Arduino framework). Each module type extends a base class handling Wi-Fi reconnect, MQTT lifecycle, watchdog reset, and OTA updates. Adding a new node type requires ~40 lines of module-specific code.

Phone access: Dashboard is fully responsive. Camera tiles reflow to single column on mobile; touch-optimized controls replace hover states. No app install required.
